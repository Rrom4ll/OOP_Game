# OOP_Game — เอกสารอธิบายโปรเจกต์ฉบับส่งต่อ

ฉบับ 17 พฤศจิกายน 2026 สำหรับสมาชิกทีม ผู้รีวิว และ AI ที่เพิ่งเข้ามาอ่าน เอกสารนี้อธิบายเกมได้ในตัวเอง ภาพและตัวเลขที่ระบุว่าเป็นตัวอย่างยังไม่ใช่เกมที่สร้างเสร็จหรือค่าที่ล็อกแล้ว

## 1. โปรเจกต์นี้คืออะไร

เกมสำรวจดันเจี้ยนผู้เล่นคนเดียว เขียนด้วย Java และเล่นบน Terminal ภาพเป็นตัวอักษร ASCII หนาแน่นที่ประกอบเป็นทางเดิน กำแพง ประตู ไอเทม และมอนสเตอร์จากมุมมองบุคคลที่หนึ่ง ผู้เล่นเริ่มตัวเปล่า ต้องหาอุปกรณ์และกุญแจ เลือกเส้นทางที่รับมือไหว และลงดันเจี้ยนลึกขึ้นโดยจัดการ HP ที่มีจำกัด

เกมใช้ภาษาอังกฤษทั้งหมด: เมนู คำสั่ง ชื่อของ ชื่อศัตรู ค่าสถานะ Inventory และข้อความเหตุการณ์ ส่วนเอกสารประกอบและการคุยงานใช้ภาษาไทยได้

อ้างอิงบรรยากาศและมุมมองจาก [Greed & Darkness บน Steam](https://store.steampowered.com/app/3538070/Greed_Darkness/) ทีมออกแบบกติกา ด่าน อาร์ต และเนื้อหาของโปรเจกต์นี้เอง การอ้างอิงไม่ได้หมายถึงนำทุกระบบของเกมต้นฉบับมาทำ

เป้าหมายการเรียนคือใช้ความรู้ Java/OOP ที่สมาชิกเรียนแล้ว สมาชิกทั้งสองคนออกแบบและเขียนส่วนของตนให้เชื่อมกันเป็นเกมที่เล่นได้

## 2. ขอบเขตและสถานะของข้อกำหนด

| สถานะ | ความหมาย |
|---|---|
| ยืนยัน | ผู้ใช้กำหนดหรือเห็นด้วยกับข้อเสนอนี้แล้ว ใช้เป็นข้อกำหนดของเกม |
| ตัวอย่าง | ภาพ ตัวเลข ผัง หรือชื่อที่ใช้ช่วยอธิบาย เปลี่ยนได้โดยไม่เปลี่ยนกติกาหลัก |
| เสนอ/รอตัดสินใจ | รายละเอียดที่ยังไม่ได้รับคำตอบชัดเจน ห้าม AI เลือกแล้วรายงานว่าเป็นความต้องการที่ยืนยัน |

สิ่งที่ยืนยัน:

- Java บน Terminal, first-person ASCII, ข้อความในเกมเป็นอังกฤษ
- เคลื่อนที่เป็นช่อง มีสี่ทิศ A/D หัน W เดินหน้า และ I เปิด Inventory
- W ต่อหน้ามอนที่อยู่ติดกันเป็นการโจมตีหนึ่งครั้ง ผู้เล่นอยู่ช่องเดิมแม้ตีจนมอนตาย
- ผู้เล่นตีก่อน มอนรอดจึงสวน มอนที่ถูกฆ่าไม่สวน
- มอนยืนประจำช่องและไม่เดินไล่ แสดงชื่อและ HP มอนที่เหลือ
- เริ่มไม่มีอุปกรณ์ ดาบ/เกราะต้อง Equip ยาต้อง Use ผ่าน Inventory
- ได้ EXP จากการฆ่า Level Up เพิ่ม max HP กับ ATK แต่ current HP คงเดิม
- ประตูต้องใช้กุญแจตรงชนิด ผัง ของ มอน และบันไดวางตายตัวทั้งหมด
- เริ่มออกแบบสองชั้น บันไดลงอย่างเดียว ย้อนกลับชั้นเดิมไม่ได้
- มีเส้นทางเลือก ใช้ดาเมจคงที่รุ่นแรก และตรวจสมดุลยา/EXP กับศัตรูที่มีจำกัด

ขอบเขตรุ่นแรกไม่มีระบบสุ่มแผนที่/ศัตรู/ของ ไม่มีศัตรูเดินไล่ และยังไม่มีระบบ respawn สำหรับฟาร์ม EXP ระบบเสียง ลอบเร้น เวทมนตร์ ร้านค้า online และ save/load ไม่อยู่ในงานหลักที่ตกลง

## 3. ประสบการณ์การเล่นตั้งแต่เริ่ม

1. เริ่มรอบใหม่ที่ตำแหน่งและทิศที่กำหนดในชั้น 1 Inventory ว่าง ไม่มีอาวุธหรือเกราะที่สวม
2. อ่าน STATUS และ CONTROLS สำรวจด้วยการหันและเดินหน้าครั้งละหนึ่งช่อง
3. พบของบนทางเดิน เก็บเข้ากระเป๋าตามวิธีที่ทีมจะเลือก การเก็บกับการใช้เป็นคนละขั้น
4. เปิด Inventory เลือกดาบแล้ว Equip ค่า ATK เพิ่มและเห็นดาบในมุมมอง เลือกเกราะแล้ว Equip ค่า DEF เพิ่ม
5. พบประตูล็อก รับข้อความว่าต้องใช้กุญแจชนิดใด สำรวจอีกทางเพื่อหากุญแจแล้วกลับมาเปิด
6. พบมอนตรงหน้า เลือกกด W แลกโจมตีทีละครั้ง หรือหันแล้วเดินไปทางอื่น มอนไม่ไล่ตาม
7. ฆ่ามอนได้ EXP ตรวจ Level Up และตัดสินใจว่าจะใช้ยาเมื่อใด เพราะ Level Up ไม่เติมเลือด
8. เลือกลงบันไดไปชั้น 2 โดยรู้ว่ากลับมาเก็บของชั้นเดิมไม่ได้
9. ผ่านความท้าทายชั้น 2 ไปถึงเงื่อนไขชนะที่ทีมจะกำหนด ถ้า HP เป็นศูนย์ให้จบรอบด้วย Game Over

จุดตัดสินใจหลักคือจะสำรวจทางไหน เอาอุปกรณ์ใดก่อน สู้หรือหลบ ใช้ยาตอนไหน และพร้อมลงชั้นถัดไปหรือยัง

## 4. โลกเป็น Grid แต่ภาพที่เห็นเป็น First Person

ข้อมูลด่านเก็บเป็นช่อง แต่ภาพหลักไม่แสดงแผนที่จากด้านบน ผู้เล่นเห็นกำแพง ทางเดิน และวัตถุจากตำแหน่ง/ทิศที่หันอยู่ ตัวอย่างแผนที่จากด้านบนในเอกสารใช้ให้ทีมออกแบบและตรวจเส้นทางเท่านั้น

- กำหนด x เพิ่มไปขวา y เพิ่มลงล่าง และเข้าถึงอาร์เรย์ด้วย `[y][x]`
- ทิศเหนือ/ตะวันออก/ใต้/ตะวันตกมีเวกเตอร์ `(0,-1)`, `(1,0)`, `(0,1)`, `(-1,0)`
- ช่องตรงหน้าคือช่องติดกันตามเวกเตอร์ทิศที่หัน ไม่ใช่มอนใดก็ได้ที่เห็นอยู่ไกล ๆ
- A หันซ้าย 90 องศา D หันขวา 90 องศา ตำแหน่งไม่เปลี่ยน
- W เคลื่อนที่เฉพาะเมื่อเป็นคำสั่งเดินสำเร็จหนึ่งช่อง ไม่มี strafe หรือเดินถอยในชุดควบคุมหลัก
- กำแพง ขอบแผนที่ ประตูปิด และมอนมีชีวิตขวางทาง

### ตารางคำสั่ง

| คำสั่ง | ผล |
|---|---|
| W | เดินหน้า หรือโจมตีมอนในช่องติดกันตรงหน้า |
| A | หันซ้าย |
| D | หันขวา |
| I | เปิด Inventory เพื่อเลือกของและ Equip/Use |

ใช้คำสั่งแล้ว Enter ในรุ่น Java พื้นฐานตามแผนรับ input ปุ่มกลับจาก Inventory/ออกเกมและการยอมรับตัวพิมพ์เล็กเป็นรายละเอียด UI ที่เสนอให้กำหนดในรอบลงมือทำ

## 5. ลำดับตัดสินใจเมื่อกด W

ลำดับนี้สำคัญต่อการเขียนโค้ดและการตรวจรับ:

1. ถ้าเกมจบแล้ว ไม่ประมวลผลการเดินหรือต่อสู้เพิ่ม
2. คำนวณพิกัดช่องติดกันตรงหน้าจากทิศที่หัน
3. ถ้ามีมอนมีชีวิตในช่องนั้น ให้ทำการโจมตีหนึ่งครั้งแล้วจบคำสั่ง W ทันที ไม่เดินต่อ
4. ถ้าเป็นกำแพง/ขอบแผนที่ ให้แจ้งว่าผ่านไม่ได้และอยู่ช่องเดิม
5. ถ้าเป็นประตูล็อก ให้ตรวจ matching key และเปิดตามกติกาประตูที่เลือก วิธีจะขยับในครั้งเปิดหรือไม่ยังรอตัดสินใจ
6. ถ้าเป็นช่องเดินผ่านได้ ให้เปลี่ยนตำแหน่งหนึ่งช่องแล้วประมวลผลสิ่งที่อยู่บนช่องนั้น เช่น ของหรือบันได
7. สร้างภาพและแสดงสถานะที่อัปเดต

**ห้ามใช้การโจมตีเป็นส่วนหนึ่งของการเดินสำเร็จ** ผู้เล่นกับมอนไม่ซ้อนช่องกัน และการฆ่ามอนไม่ทำให้เดินเข้าแทนที่ในคำสั่งเดียวกัน W ครั้งใหม่หลังมอนตายจึงเดินเข้าช่องที่ว่างได้

## 6. การต่อสู้โดยละเอียด

มอนมีชื่อ HP/current และ max, ATK, ค่า EXP และตำแหน่งคงที่ ระหว่างการต่อสู้ใช้ค่าที่กำหนดไว้ ไม่มี critical hit, dodge หรือ random damage ในรุ่นแรก

1. รับ W เมื่อมอนอยู่ติดกันตรงหน้า
2. คำนวณ ATK ผู้เล่นจากค่าพื้นฐาน โบนัส Level และอาวุธที่ Equip อยู่
3. ลด HP มอน แสดงดาเมจและ HP มอนที่เหลือ โดย HP ต่ำสุดเป็น 0
4. ถ้า HP มอนเป็น 0 ให้เปลี่ยนสถานะเป็นตาย ให้ EXP ครั้งเดียว แล้วตรวจ Level Up ไม่เรียกการสวนกลับ
5. ถ้ามอนรอด ให้มันสวนหนึ่งครั้ง ลดดาเมจตามเกราะที่ Equip และอัปเดต HP ผู้เล่น
6. ถ้า HP ผู้เล่นเป็น 0 ให้ Game Over
7. ตำแหน่งผู้เล่นไม่เปลี่ยนทุกกรณีในคำสั่งโจมตีนี้

ตัวอย่างที่ 1: โจมตีแล้วมอนรอด ตัวเลขเพื่ออธิบายเท่านั้น

```text
You hit Goblin for 7 damage.
Goblin HP: 5/12
Goblin hits you for 3 damage.
Your HP: 17/20
```

ตัวอย่างที่ 2: W ครั้งถัดมาฆ่าได้

```text
You hit Goblin for 7 damage.
Goblin HP: 0/12
Goblin defeated. You gained 5 EXP.
Your HP: 17/20
```

ค่าดาเมจในข้อความเป็นพลังโจมตีที่คำนวณได้ ในตัวอย่างครั้งที่สอง HP มอนเหลือ 5 แต่ถูกโจมตีด้วยพลัง 7 จึง clamp HP ลงที่ 0 ถ้าทีมเลือกให้แสดงเฉพาะ HP ที่ถูกหักจริง ข้อความต้องเปลี่ยนเป็น 5 และกำหนดรูปแบบนั้นให้สม่ำเสมอ

### การหนีและการกระทำอื่น

หากยังไม่อยากสู้ต่อ ผู้เล่นหันด้วย A/D แล้ว W ไปช่องที่ผ่านได้ มอนยืนที่เดิม การหันหรือเดินหนีไม่ใช่การโจมตีมอนด้านข้าง

ข้อเสนอที่ยังไม่ได้ยืนยันแยก: มอนสวนเฉพาะเมื่อถูกตีแล้วรอด การเปิดกระเป๋า หัน และใช้ยาจึงไม่ทำให้มันโจมตีเอง ห้ามนำระบบมอนโจมตีหลังทุกตาจากแผนเก่ากลับมาโดยอัตโนมัติ ผลของการใช้ยาขณะอยู่หน้ามอนต้องสรุปก่อนเขียน flow นี้

## 7. ผู้เล่นและค่าสถานะ

| ค่า | ความหมาย |
|---|---|
| Floor | ชั้นดันเจี้ยนปัจจุบัน |
| Level | ระดับผู้เล่น เริ่มระดับแรกตามตารางสมดุล |
| HP | เลือดปัจจุบันที่ลดจากการถูกโจมตีและฟื้นด้วยยา |
| Max HP | เพดานเลือด เพิ่มเมื่อ Level Up |
| EXP | ประสบการณ์จากการฆ่า ใช้ตรวจเกณฑ์เลเวลถัดไป |
| ATK | ค่าการโจมตีที่รวมโบนัสจาก Level และอาวุธที่ Equip |
| DEF | ค่าป้องกันจากเกราะที่ Equip |
| Weapon / Armor | อุปกรณ์ที่สวมจริง แยกจากของที่มีใน Inventory |

ตัวอย่างสูตรเรียบง่าย:

```text
Player ATK = baseAttack + levelAttackBonus + equippedWeaponBonus
Received damage = enemyAttack - equippedArmorDefense
```

สูตรขั้นต่ำของดาเมจว่าจะ clamp ที่ 0 หรือ 1 ยังรอเลือก ตัวเลขสมดุลและเงื่อนไขค่าที่ไม่ถูกต้องต้องรวมไว้เป็นข้อมูลที่ค้นหาได้ง่าย

เมื่อเขียนโบนัส Level ให้เลือกวิธีเก็บอย่างใดอย่างหนึ่ง: เก็บ baseAttack เริ่มต้นแล้วคำนวณ levelBonus หรือเพิ่มค่าพื้นฐานโดยตรงตอน Level Up อย่าเพิ่มค่าพื้นฐานแล้วบวกโบนัสระดับซ้ำอีกครั้ง

ตัวอย่างชุดตัวเลขที่ใช้ในภาพประกอบ ไม่ใช่ค่าที่อนุมัติแล้ว:

| รายการ | ค่าตัวอย่าง |
|---|---|
| ผู้เล่นเริ่มต้น | Level 1, HP 20/20, base ATK 2, DEF 0 |
| Iron Sword | ATK +5 เมื่อ Equip รวมเป็น ATK 7 |
| Leather Armor | DEF +2 เมื่อ Equip |
| Goblin | HP 12, ATK 5, EXP reward 5 |
| เลเวล 1 → 2 | ใช้ EXP 10, max HP +5, base ATK +1 |

ตัวอย่างนี้อธิบายว่าดาบช่วยลดจำนวนครั้งที่ต้องแลกเลือด และเกราะช่วยลดความเสียหายแต่ละครั้ง ค่าจริงต้องตรวจพร้อมทั้งด่าน

## 8. EXP และ Level Up

- มอนแต่ละตัวให้ EXP ตามค่าที่กำหนดเมื่อถูกฆ่า ไม่ได้ EXP ทุกครั้งที่ตี
- มอนที่ตายแล้วไม่ให้ EXP ซ้ำ ไม่มี respawn ให้ฆ่าซ้ำในรุ่นแรก
- เมื่อถึงเกณฑ์ เพิ่ม Level, max HP และ ATK **ไม่เพิ่ม current HP**
- ตัวอย่าง HP 12/20 กลายเป็น 12/25 ผู้เล่นต้องหายาเพื่อใช้พื้นที่เลือดที่เพิ่มขึ้น
- เสนอให้ EXP ส่วนเกินเก็บต่อ และตรวจ Level ซ้ำเมื่อ EXP พอหลายระดับ ไม่ปัดส่วนเกินทิ้งโดยไม่ได้ตกลง

```text
Level Up! You are now Level 2.
Max HP increased to 25. Your HP remains 12.
Base ATK increased to 3.
```

ทีมต้องเลือกว่าจะแสดง EXP แบบสะสมทั้งหมดหรือ EXP ของระดับปัจจุบัน และใช้รูปแบบเดียวกันทั้ง HUD/Inventory/log

## 9. Inventory อาวุธ เกราะ และยา

แยกสามสถานะให้ชัด: ของอยู่ในด่าน → ของอยู่ใน Inventory → ของถูก Equip/Use แล้ว

| ชนิด | การใช้งาน |
|---|---|
| Weapon | เปิด Inventory เลือก Equip แล้วเพิ่ม ATK/แสดงภาพดาบ |
| Armor | เปิด Inventory เลือก Equip แล้วเพิ่ม DEF/ลดดาเมจที่ได้รับ |
| Potion | เปิด Inventory เลือก Use แล้วฟื้น HP ไม่เกิน max HP |
| Key | อยู่ในกระเป๋าเพื่อให้ประตู matching key ตรวจพบ ไม่ต้อง Equip เป็นอาวุธ |

มีดาบในกระเป๋าอย่างเดียวต้องยังตีแบบมือเปล่า มีเกราะในกระเป๋าอย่างเดียวต้องยังไม่ลดดาเมจ ผู้เล่นเริ่มไม่มีภาพดาบ ภาพจะแสดงเมื่อมีดาบที่ Equip จริง

รายละเอียดที่เสนอ: มีช่อง Weapon หนึ่งช่องและ Armor หนึ่งช่อง การเปลี่ยนของให้แทนช่องเดิมแทนการบวกโบนัสซ้ำ ยาใช้สำเร็จแล้วลดจำนวน เลือดเต็มแล้วไม่เสียยา กระเป๋ารุ่นแรกไม่จำกัดน้ำหนักและไม่ต้องมีระบบทิ้งของ รายละเอียดเหล่านี้ยังต้องเลือกตามขอบเขตจริง

ตัวอย่าง Inventory ด้านล่างเป็น UI ร่าง หมายเลขและปุ่ม 0 เป็นข้อเสนอ ไม่ใช่คำสั่งเพิ่มเติมที่ผู้ใช้ยืนยันแล้ว:

```text
+--------------------------------------------------------------------------+
```

## 10. ประตู กุญแจ และบันได

ผู้เล่นเดินชนประตูด้วย W ประตูตรวจชนิดกุญแจ เช่น Copper Door ต้องใช้ Copper Key การมีกุญแจชนิดอื่นไม่ควรเปิดได้

```text
Locked. Requires Copper Key.
You unlocked Copper Door with Copper Key.
```

สองรายละเอียดที่ยังรอเลือก: ใช้แล้วกุญแจหายหรือเก็บไว้ และคำสั่ง W ที่เปิดประตูสำเร็จจะอยู่ช่องเดิมหรือเดินเข้าช่องประตูทันที ประตูที่เปิดแล้วควรคงสถานะเปิดเพื่อไม่ใช้ของซ้ำ

บันไดลงวางตำแหน่งตายตัว เมื่อใช้งานจะไปจุดเริ่มชั้นถัดไปที่กำหนดไว้ ย้อนขึ้นไม่ได้ เสนอให้ส่งต่อ HP, Level, EXP, กระเป๋า และอุปกรณ์ทั้งหมด ไม่เริ่มตัวละครใหม่ตอนเปลี่ยนชั้น

```text
You descend to Floor 2.
There is no way back.
```

เสนอให้บอกผู้เล่นก่อนลงว่ากลับไม่ได้ ถ้าเลือกลงทันทีเมื่อเดินถึง ให้แสดงคำเตือนตั้งแต่ผู้เล่นอยู่หน้าบันไดก่อนกด W ถ้าเลือกถามยืนยัน ให้เตือนในกรอบยืนยันก่อนเปลี่ยนชั้น รูปแบบนี้ยังเป็นรายละเอียด UI ที่ทีมต้องเลือก ไม่ควรเตือนหลังเปลี่ยนชั้นไปแล้ว

## 11. แนวทางออกแบบสองชั้น

### ชั้น 1: เรียนรู้การเอาตัวรอด

สอนทีละระบบ: จุดเริ่ม → มองเห็นของ → เก็บดาบ → เข้า Inventory เพื่อ Equip → เจอมอนอ่อน → พบประตูล็อก → หา matching key → เปิดทาง → พบยา/เกราะ → บันไดลง

ให้เห็นเหตุผลของการสำรวจ เช่น ผ่านมอนมือเปล่าได้แต่เสียเลือดมาก ถ้าหาดาบก่อนจะเสียเลือดน้อยลง ต้องไม่บังคับให้ผู้เล่นที่ไม่มีของแพ้ทันทีตั้งแต่เริ่มโดยไม่มีทางเลือก

### ชั้น 2: ใช้ความเข้าใจจากชั้นแรก

จัดเส้นทางสั้นที่อันตรายกับทางอ้อมที่มีทรัพยากร ใช้ศัตรูและประตูที่วางไว้ตายตัว ทดสอบว่าจำนวนยา EXP และของที่นำลงมาทำให้มีเส้นทางชนะที่สมเหตุสมผล

ตัวอย่าง flow เพื่อคุยงาน ไม่ใช่แผนที่ล็อกแล้ว:

```text
Floor 1
Start -> Sword -> Goblin -> Locked Door -> Armor -> Stairs Down
             \-> Side Passage -> Copper Key --/

Floor 2
Entry -> Short Dangerous Route ---------> Final Objective
      \-> Longer Route -> Potion ------/
```

การสิ้นสุดเกมยังต้องเลือก เสนอให้มีทางออกท้ายชั้น 2 เป็นจุดจบอย่างง่าย ห้ามถือว่ามีบอสหรือเพิ่มชั้นใหม่จนกว่าทีมจะเลือก

## 12. หน้าจอและภาพ ASCII ที่ต้องการ

ภาพหลักอยู่ตรงกลาง ซ้ายบนแสดง STATUS กรอบ CONTROLS อธิบายคำสั่งอยู่ตลอด กรอบ ENEMY แสดงชื่อ/HP ศัตรูที่อยู่ตรงหน้า และด้านล่างเป็นบันทึกเหตุการณ์ ภาพต้องเปลี่ยนตามตำแหน่ง ทิศ สถานะประตู และศัตรูที่ยังมีชีวิต

ใช้ตัวอักษรเล็กจำนวนมากสร้างแสงเงาและความลึก ตัวอย่างลำดับความหนา ` .,:;irsXA253hMHGS#9B&@` ต้องปรับตามฟอนต์จริง ใช้ monospace พื้นดำและเริ่มจากขาวเทา สีเป็นงานขยาย

เฟรมเป้าหมาย: 120 × 40 และโหมดละเอียด 160 × 50 ช่อง เป็นความละเอียดตัวอักษรทั้งจอ ไม่ใช่จำนวนพิกเซล เผื่อความกว้าง/สูง Terminal และตำแหน่งรับคำสั่งเพื่อป้องกันการตัดบรรทัด

กรอบ log ในตัวอย่างมีพื้นที่เหตุการณ์ 4 บรรทัดและ Command 1 บรรทัด เมื่อโจมตีแล้วฆ่า/ได้ EXP/Level Up พร้อมกัน เสนอให้สรุปเป็นบรรทัดสั้นที่ยังเก็บข้อมูลสำคัญครบ แทนการพิมพ์ log ยาวจนเฟรมเลื่อน ตัวอย่าง Level Up หลายระดับให้รวมเป็น `Level 1 -> 3` หนึ่งบรรทัด:

```text
You hit Goblin for 7 damage. Goblin HP: 0/12.
Goblin defeated. +5 EXP.
Level 2! Max HP: 25 | HP: 17 unchanged | Base ATK: 3
Your position did not change.
Command > _
```

ตัวอย่างข้อความแยกในหัวข้อก่อนหน้าอธิบายเหตุการณ์เชิงตรรกะ ไม่ได้บังคับให้พิมพ์เป็นจำนวนบรรทัดเท่ากันในทุกขนาดหน้าจอ

ภาพต่อไปนี้เป็นข้อความ ASCII ต้นฉบับที่สร้างเพื่อสื่อสารแบบเกม ไม่ใช่ภาพจากเกมที่พัฒนาเสร็จ คุณภาพภาพจริงยังต้องทดลองฟอนต์ สัดส่วน และวิธีแสดงผล

## 13. การเขียนภาพโดยไม่ทำให้กติกาปนกัน

เก็บแผนที่เป็นข้อมูลสองมิติ ใช้สถานะตัวละครและทิศตรวจสิ่งที่มองเห็น งานทดลองเริ่มจากฉากระยะใกล้/กลาง/ไกลด้วยพิกัดและลูปที่ทีมอธิบายได้ Ray Casting เป็นทางเลือกหลังเรียนรู้ ไม่ใช่ข้อบังคับของโปรเจกต์

- ภาพศัตรู/ของหลังผนังหรือประตูปิดต้องไม่ปรากฏ
- มอนที่ตายแล้วหายจากฉาก แต่พิกัดผู้เล่นไม่เลื่อนตามภาพ
- แสดงดาบตาม equippedWeapon ไม่ใช่เพียงตรวจว่ามี Weapon อยู่ในกระเป๋า
- renderer อ่านสถานะและสร้างข้อความ ไม่ลด HP ไม่ให้ EXP และไม่เปิดประตู
- ส่วน Terminal รวมฉาก STATUS/CONTROLS/enemy HP/log แล้วพิมพ์เป็นเฟรมเดียว ใช้ ANSI เมื่อรองรับและมีทางแสดงผลพื้นฐานได้
- ไม่มีข้อกำหนดให้ทำ animation, real-time input หรือ thread ในรุ่นแรก

## 14. คลาสและความรู้ Java/OOP

โครงสร้างที่เสนอให้สมาชิกเขียนเอง ไม่ใช่คลาสที่มี implementation แล้ว:

| คลาส | หน้าที่ |
|---|---|
| Main | จุดเริ่มโปรแกรม |
| Game | ควบคุมคำสั่ง โดยเฉพาะ W ตรวจมอนก่อนเดิน ประสานกติกาและตรวจจบเกม |
| Dungeon | ข้อมูลแผนที่สองชั้น พิกัด ช่องเดิน ของ มอน ประตู และจุดลงบันได |
| Player | HP/max HP, EXP/Level, ตำแหน่ง/ทิศ, Inventory และอุปกรณ์ที่สวม |
| Enemy | HP, ATK, EXP reward และสถานะตาย |
| Door | required key และสถานะล็อก/เปิด |
| Item | ข้อมูลร่วมและรายละเอียดไอเทม |
| Key / Potion / Weapon / Armor | รายละเอียดของแต่ละชนิด สืบทอด Item |
| AsciiRenderer | ภาพฉากจากสถานะและทิศ |
| TerminalDisplay | รับคำสั่ง Inventory, STATUS/CONTROLS/log และพิมพ์ภาพรวม |

ใช้ encapsulation คุม HP/การใช้ของ, inheritance สำหรับ Item, polymorphism ตอนแสดงรายละเอียด Item, composition/association สำหรับกระเป๋าและอุปกรณ์ ใช้ if/switch/loop/array/ArrayList ตามเนื้อหาที่ทีมยืนยัน UML และ CRC อธิบายความรับผิดชอบก่อนลงมือ

เอกสารเรียนที่พบและขอบเขตความรู้เสริมอยู่ใน [COURSE_SCOPE](COURSE_SCOPE.md) ต้องยืนยันว่า CSS232/LabOOP232 เป็นชุดวิชาที่ประเมินจริง และเลือกรุ่น JDK ร่วมกัน

## 16. เกณฑ์สำคัญที่ใช้ตรวจว่าเข้าใจเกมตรงกัน

1. กด W ตีมอนที่ยังรอด: พิกัดผู้เล่นเท่าเดิม HP มอนลด มอนสวนครั้งเดียว
2. กด W ฆ่ามอน: พิกัดเท่าเดิม มอนไม่สวน HP แสดง 0 ได้ EXP ครั้งเดียว
3. กด W อีกครั้งหลังมอนตาย: จึงเดินเข้าช่องที่ว่างได้
4. มอนอยู่ด้านข้าง/หลัง/ไกลเกินหนึ่งช่อง: W ไม่โจมตีมัน
5. หันแล้วเดินหนี: มอนอยู่ที่เดิม
6. เก็บดาบแต่ไม่ Equip: ATK/ภาพดาบยังเหมือนมือเปล่า เกราะก็ใช้หลักเดียวกัน
7. Level Up: max HP/ATK เพิ่ม current HP คงเดิม
8. กุญแจผิดชนิดเปิดประตูไม่ได้ ประตูที่เปิดแล้วไม่กลับไปล็อกเอง
9. ลงชั้นสองแล้วกลับไม่ได้ ส่งต่อสถานะผู้เล่นตามกติกาที่เลือก
10. ทุกข้อความที่แสดงแก่ผู้เล่นเป็นอังกฤษ เห็น HP มอนที่เหลือและค่าความเสียหายชัดเจน
11. เริ่มรอบใหม่แล้วแผนที่ ของ มอน และประตูกลับสภาพเริ่มต้นตามตำแหน่งเดิมทั้งหมด
12. clone ไปเครื่องเพื่อน compile และเล่นครบได้ตาม README ที่บันทึกคำสั่งผ่านจริง

## 17. เรื่องที่ยังต้องเลือกก่อน implementation ส่วนนั้น

| เรื่อง | ตัวเลือก/ข้อเสนอที่ต้องตัดสินใจ |
|---|---|
| การเก็บของ | เดินเข้าแล้วเก็บอัตโนมัติ หรือมีคำสั่งเก็บ |
| การใช้ยา/เปิดกระเป๋าต่อหน้ามอน | เสนอให้ไม่มีการสวนเอง แต่ยังไม่ได้ยืนยันแยก |
| กุญแจ | ใช้แล้วหาย หรือเก็บไว้ใช้ต่อ |
| เปิดประตูสำเร็จด้วย W | อยู่ช่องเดิม หรือเดินเข้าช่องประตูทันที |
| กระเป๋า/เปลี่ยนอุปกรณ์ | จำนวนช่อง วิธีแทนของเดิม วิธีเลือกหมายเลข และคำสั่งกลับ |
| ยาขณะเลือดเต็ม | เสนอว่าไม่เสียยา แต่ยังต้องเลือกนโยบายการใช้/หักจำนวน |
| ดาเมจขั้นต่ำ | 0 หรือ 1 หลังหัก DEF |
| ข้อความดาเมจเมื่อโจมตีเกิน HP | แสดงพลังโจมตีเต็ม หรือแสดงเฉพาะ HP ที่ถูกหักจริง |
| ตัวเลขสมดุล | ค่าเริ่มต้น ของ มอน ยา EXP threshold และโบนัส Level |
| EXP | รูปแบบ HUD แบบสะสม/เฉพาะ Level และการเก็บ EXP ส่วนเกิน/ข้ามหลาย Level |
| เปลี่ยนชั้น | ลงทันทีเมื่อเดินถึง หรือแสดงคำเตือน/ยืนยันก่อนลง |
| สถานะข้ามชั้น | เสนอให้รักษา HP, Level, EXP, Inventory และอุปกรณ์ที่สวมทั้งหมด |
| นโยบาย log | สรุปให้พอดี หรือมีประวัติ/แบ่งหน้าเมื่อข้อความยาว |
| การชนะ | เสนอทางออกปลายชั้นสอง เงื่อนไขจริงยังไม่ได้เลือก |

ข้อเสนอเพิ่มเติมต้องแยกจากกติกาที่ยืนยัน อย่าเพิ่มปุ่ม F/P/S, auto-equip, มอนเดิน, random map, level-up heal, การตีแล้วเดินเข้าช่องมอนทันที หรือระบบใหญ่ที่ไม่ได้อยู่ในขอบเขต
