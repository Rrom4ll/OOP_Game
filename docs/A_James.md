# A (James)

Branch: `feat/world-view`

รับผิดชอบโลกเกม การควบคุม ภาพ ASCII หน้าจอทั้งหมด และการรวมงานเข้า main

อ่าน [กติกาเกม](GAME_DESIGN.md) และ [constructor/API ที่ใช้ร่วมกัน](PROJECT_PLAN.md) ก่อนเขียนส่วนเชื่อม งานของ Jezz อยู่ใน [B_Jezz](B_Jezz.md)

## ไฟล์ที่ดูแล

| ไฟล์ | หน้าที่ |
|---|---|
| Main.java | สร้าง Game และเริ่มโปรแกรม |
| Game.java | คุมคำสั่ง สถานะ การเดิน/ตี/Inventory เปลี่ยนชั้น และจบเกม |
| Dungeon.java | แผนที่ จุดเริ่ม ตำแหน่งของ/มอน/ประตู/บันได/ทางออก |
| Door.java | matching key และสถานะล็อก/เปิด |
| Key.java | สืบทอด Item เก็บ keyId และรายละเอียดกุญแจ |
| AsciiRenderer.java | สร้างภาพฉากจากโลก ตำแหน่ง และทิศ |
| TerminalDisplay.java | รับคำสั่ง พิมพ์ฉาก STATUS/CONTROLS/ENEMY/log และเมนู |

ดูแลอาร์ตทั้งหมด รวมกำแพง ประตู มอน ดาบ ของ และหน้าจอเริ่ม/แพ้/ชนะ

## เริ่มทำอะไรก่อน

1. เข้า feat/world-view จากฐาน main
2. ออกแบบแผนที่ทดลองหนึ่งชั้นให้มีทางเดิน กำแพง และจุดเริ่ม
3. ทดลองภาพ First Person จากสี่ทิศและกรอบ STATUS/CONTROLS
4. ระหว่างนั้น Jezz ทำโครงหกคลาสและ Player/Item พื้นฐาน
5. หลังฐาน Jezz เข้า main ให้นำ main เข้า branch ตัวเอง แล้วเชื่อม Game กับ Player ตาม API
6. เปลี่ยน Main.java ให้เรียก Game เมื่อ loop สำรวจพร้อม

โค้ดที่เชื่อม Player/Enemy/Item ต้องใช้ฐานจาก Jezz ไม่สร้างคลาสชื่อเดียวกันซ้ำเพื่อแก้ compile

## งานที่ต้องทำ

### 1. การเดินและโลกเกม

- ใช้พิกัด `[y][x]` และทิศ 0 เหนือ, 1 ตะวันออก, 2 ใต้, 3 ตะวันตก
- รับ W/A/D จาก TerminalDisplay แล้ว Game ตรวจเงื่อนไข
- A/D หัน 90 องศา ส่วน W ตรวจเฉพาะช่องติดกันตรงหน้า
- กำแพง ขอบด่าน ประตูปิด และมอนมีชีวิตขวางทาง
- เปลี่ยนตำแหน่ง/ทิศผ่าน Player.moveTo()/setDirection() หลัง Game ตรวจด่านแล้ว
- วางของ/มอน/ประตู/บันไดไม่ทับช่องเดียวกัน ทุกจุดกำหนดตายตัว

### 2. เชื่อมการโจมตี

```text
W เจอมอนมีชีวิตตรงหน้า
  -> player.attack(enemy)
  -> แสดงดาเมจและ HP มอน
  -> มอนรอด: enemy.attack(player) หนึ่งครั้ง
  -> มอนตาย: gainExp(reward) ครั้งเดียว แล้วนำมอนออกจากด่าน
  -> ตรวจแพ้ แสดงผล และจบคำสั่ง
```

พิกัดผู้เล่นต้องไม่เปลี่ยนทุกกรณี รวมถึงตอนฆ่ามอนตาย W ครั้งถัดไปจึงเดินเข้าช่องว่าง ห้ามเขียนสูตรโจมตีซ้ำใน Game หรือ renderer

### 3. ของ กุญแจ และประตู

- เดินถึงของแล้วเพิ่มเข้า Player สำเร็จจึงนำของออกจากด่าน
- Key ใช้ protected Item(String name) และ override getDescription() ตาม API ของ Jezz
- Door อ่าน Player.getItems() เพื่อหา Key ที่ keyId ตรงกัน
- ตรวจครบก่อน removeItem(key) แล้วเปลี่ยนประตูเป็นเปิด
- เปิดด้วย W แล้วอยู่ช่องเดิม ใช้กุญแจหนึ่งชิ้น ประตูเปิดถาวร
- ไม่มีกุญแจที่ตรงกันให้แสดงข้อความและไม่เปลี่ยนข้อมูล

### 4. Inventory และเมนู

- I เปิดรายการ 0 กลับหน้าปกติ Q ออกเกม
- แสดงชื่อ รายละเอียด และสถานะ Equip พร้อมหมายเลข
- Game แปลหมายเลข แล้วเรียก equipWeapon/equipArmor/usePotion ตามชนิด
- เลือก Key ให้แสดงรายละเอียด ใช้จริงที่ประตู
- TerminalDisplay มีหน้าที่พิมพ์และอ่านคำสั่ง ไม่เปลี่ยน HP/อุปกรณ์เอง
- คำสั่งผิดไม่ใช้ของ EOF ออกโปรแกรม ทุกข้อความเป็นอังกฤษ

### 5. ภาพและหน้าจอ

- เริ่มเฟรม 120×40 ช่อง ให้ภาพตรงตำแหน่งและทิศ
- STATUS ซ้ายบน ฉากกลาง CONTROLS ขวา พร้อมชื่อ/HP มอนตรงหน้าและ log ด้านล่าง
- มอน/ของหลังผนังหรือประตูปิดต้องมองไม่เห็น
- ดาบแสดงเมื่อ getEquippedWeapon() ไม่เป็น null เท่านั้น
- รวมภาพและข้อความเป็นหนึ่งเฟรมก่อนพิมพ์
- คงข้อมูลสำคัญเมื่อฆ่ามอน/ได้ EXP/Level Up ในคำสั่งเดียว โดยไม่ล้นกรอบ
- ใช้ตัวอย่างใน [ART_GUIDE](ART_GUIDE.md) เป็นจุดเริ่ม แล้วปรับรูปทรงให้เข้ากับ renderer

### 6. สองชั้นและจบเกม

- จุดเริ่มแต่ละชั้นวางตายตัว ลงได้อย่างเดียว
- เตือนเมื่อผู้เล่นอยู่หน้าบันได แล้วเดินเข้าช่องจึงเปลี่ยนชั้น
- ส่งต่อ Player เดิมพร้อม HP/EXP/Level/กระเป๋า/อุปกรณ์ ไม่สร้างตัวละครใหม่ตอนลงชั้น
- ทางออกท้ายชั้น 2 ทำให้ชนะ HP 0 ทำให้แพ้
- เมนูจบเกมใช้ R เริ่มใหม่ Q ออก เริ่มใหม่แล้วสร้างโลกและผู้เล่นเริ่มต้นใหม่

## สิ่งที่รับจาก Jezz

- constructor และเมธอดของ Player/Enemy/Item ตาม [PROJECT_PLAN](PROJECT_PLAN.md)
- HP/ATK/DEF/EXP/Level และอุปกรณ์ที่สวมสำหรับแสดงผล
- `List<Item>` อ่านอย่างเดียว ใช้ addItem/removeItem แทนการแก้รายการตรง ๆ
- attack() คืน HP ที่หักจริง; gainExp() เปลี่ยน Level โดยไม่ Heal

ถ้าต้องเปลี่ยน API ที่ใช้อยู่ให้ตกลงกับ Jezz ก่อนแก้จุดเรียก

## ความรู้ที่ใช้

| แนวคิด | ใช้กับงาน |
|---|---|
| Array / Loop | ด่านและภาพ ASCII |
| if / switch / Scanner / String | คำสั่ง เมนู และข้อความ |
| Class / Constructor | แยก Game, Dungeon, Door และหน้าจอ |
| Inheritance / Overriding | Key extends Item |
| OOAD / CRC / GRASP | แบ่งหน้าที่ Game กับโลก/หน้าจอ |
| Sequence / Activity | ไล่ W เพื่อไม่เดินต่อหลังโจมตี |
| State / Guard | คุมหน้าปกติ/Inventory/จบเกม และเปิดประตูเมื่อเงื่อนไขครบ |
| Layering | หน้าจออ่านข้อมูล ไม่คำนวณการต่อสู้อีกชุด |

รายละเอียดแนวคิดเพิ่มเติมอยู่ใน [COURSE_SCOPE](COURSE_SCOPE.md)
