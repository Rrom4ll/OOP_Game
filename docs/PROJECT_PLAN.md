# แผนงานเกม Java Terminal ASCII

แผนงานสำหรับ A (James) และ B (Jezz) อัปเดตการแบ่งงานวันที่ 18 พฤศจิกายน 2026

รายละเอียดงานและ Git รายคน: [James](A_James.md) / [Jezz](B_Jezz.md) และ [flow รวมงาน](TEAM_WORKFLOW.md)

กติกาที่ผู้ใช้ยืนยันและรายละเอียดที่ยังต้องเลือกอยู่ใน [GAME_DESIGN](GAME_DESIGN.md) ให้ยึดเอกสารนั้นเมื่อเขียนระบบเกม

## 1. เป้าหมายและประสบการณ์เล่น

เกมมุมมองบุคคลที่หนึ่งบน Terminal ภาพประกอบด้วยตัวอักษร ASCII ขนาดเล็กจำนวนมาก อ้างอิงบรรยากาศสำรวจดันเจี้ยนจากภาพตัวอย่างของผู้ใช้ ทีมออกแบบฉาก ศัตรู และกติกาของตนเอง

เส้นทางเล่นหลัก: สำรวจ → เก็บกุญแจและอาวุธ → เปิดประตู → จัดการศัตรู → ไปถึงทางออก

รุ่นส่งงานพื้นฐาน (MVP):

- เป้าหมายสองชั้นที่วางทุกอย่างล่วงหน้า เริ่มทดลองหนึ่งชั้นประมาณ 15 × 15 ช่องก่อน แล้วเชื่อมชั้นสองใน M4
- ผู้เล่นเริ่มไม่มีอุปกรณ์ มีตำแหน่ง ทิศ HP/current และ max, EXP, Level, ATK, DEF และช่องอาวุธ/เกราะที่ Equip
- กำแพง ประตูที่ต้องใช้กุญแจตรงชนิด และบันไดลงชั้นถัดไป กลับชั้นก่อนหน้าไม่ได้ ส่วนเงื่อนไขชนะท้ายชั้นสองรอเลือก
- มีดาบ เกราะ ยา และศัตรูประจำช่อง จำนวนและค่าพลังจริงกำหนดในตารางสมดุลหลังทดลอง
- กระเป๋าไอเทม เปิดประตู ต่อสู้ ผลชนะ/แพ้ เริ่มใหม่ และออกเกมได้
- ภาพมุมมองบุคคลที่หนึ่งพร้อม HUD และข้อความเหตุการณ์ ทดสอบทั้ง 120 × 40 และ 160 × 50 ช่อง
- ข้อความในเกมเป็นอังกฤษทั้งหมด STATUS ซ้ายบน ภาพตรงกลาง กรอบ CONTROLS และข้อมูล HP ศัตรู/บันทึกการต่อสู้

สมบัติ ระบบเสียงเตือนศัตรู ย่องเบา ลอบโจมตี บันทึกเกม การเดินแบบทันที และชั้นเพิ่มเติมจากสองชั้น เป็นงานขยายหลังเล่นจบได้ครบแล้ว ไม่มีระบบสุ่มในขอบเขตที่ตกลง

## 2. กติกา

| คำสั่ง | พฤติกรรม |
|---|---|
| W + Enter | ถ้ามีมอนมีชีวิตในช่องติดกันตรงหน้า ให้ตีหนึ่งครั้งและอยู่ช่องเดิม ถ้าเป็นทางที่ผ่านได้จึงเดินหนึ่งช่อง |
| A / D + Enter | หันซ้าย / ขวา 90 องศา |
| I + Enter | เปิด Inventory เพื่อเลือก Equip ดาบ/เกราะ หรือ Use ยา |

- การโจมตีไม่เปลี่ยนตำแหน่ง แม้ตีจนมอนตาย ผู้เล่นตีก่อนและมอนสวนเฉพาะเมื่อรอด ไม่มีการโจมตีเป้าหมายข้างตัวหรือด้านหลังด้วย W
- แสดงชื่อมอน ดาเมจ และ HP ที่เหลือทุกครั้ง เช่น `Goblin HP: 5/12` ฆ่าได้ EXP ครั้งเดียวและมอนไม่เกิดใหม่
- มอนยืนช่องเดิม ผู้เล่นหนีด้วยการหันแล้วเดินไปทางที่ผ่านได้
- เก็บดาบ/เกราะแล้วต้องเลือก Equip ใน Inventory จึงได้โบนัส ภาพดาบแสดงตามอุปกรณ์ที่สวมจริง
- Level Up เพิ่ม max HP และ ATK แต่ current HP คงเดิม ต้องใช้ยาเอง
- เดินชนประตูเปิดได้เมื่อมี matching key การหักกุญแจและการเดินผ่านในคำสั่งเปิดครั้งเดียวกันยังรอเลือก
- เงื่อนไขการใช้ยาต่อหน้ามอน การเก็บของ และผลลัพธ์ท้ายชั้นสองยังเปิดไว้ใน GAME_DESIGN
- ถ้ารับ input สิ้นสุด (EOF) ให้ออกอย่างเรียบร้อย รายละเอียด UI กำหนดตอนทำ Terminal

ค่าความเสียหาย การลดดาเมจ เกณฑ์ EXP โบนัส Level และการฟื้นเลือดให้ทีมกำหนดเป็นตาราง แล้วเล่นลองจริง ไม่ควรปรับค่ากระจายหลายไฟล์

## 3. วิธีแสดงภาพและงานทดลองที่จำเป็น

ภาพ ASCII ละเอียดกับการคำนวณสามมิติเป็นคนละเรื่อง ตัวอักษรหนาแน่นสร้างได้ด้วยลูปและพื้นผิวตัวอักษร แต่การเลือกว่าต้องวาดอะไรจากมุมมองผู้เล่นต้องมีวิธีคำนวณที่ทีมเข้าใจ

งาน M1 ให้ทดลองก่อนเลือกวิธีหลัก:

1. ตรวจแผนที่ในทิศที่ผู้เล่นหัน วาดกรอบกำแพงใกล้/กลาง/ไกลในระยะ 1–3 ช่องด้วยพิกัดที่กำหนดไว้
2. ใช้ลูปเติมพื้นผิวและแสงเงาภายในพื้นที่กำแพง วาดฉากไกลก่อนแล้วฉากใกล้ทับ พร้อมปิดบังสิ่งหลังผนังหรือประตูปิด
3. ทดลองทางตรง ทางตัน ทางแยกซ้าย/ขวา สี่แยก และการหันครบสี่ทิศ ถ้ารูปทรงซับซ้อนเกินเวลาของรอบทดลอง ให้ลดระยะที่มองเห็นและปรับแผนที่ให้เรียบง่าย
4. ถ้าทีมเข้าใจตรีโกณมิติและมีเวลา อาจทดลอง Ray Casting เป็นอีกทางเลือก เก็บผลทดลองและอธิบายระยะ ความสูงผนัง และสัดส่วนช่องตัวอักษรให้ได้ก่อนนำเข้าเกม

ผล M1 ต้องยังเป็นภาพบุคคลที่หนึ่ง การลดความซับซ้อนให้ลดระยะ/รายละเอียดก่อน ไม่มีข้อผูกมัดว่าต้องทำ Ray Casting เต็มระบบ ความละเอียดสูงเป็นเป้าหมายที่ต้องตรวจความอ่านง่ายและเวลาในการทำจริง

แยกการสร้างเฟรมออกจากการพิมพ์ ใช้บัฟเฟอร์ข้อความหนึ่งเฟรม พิมพ์ครั้งเดียว และใช้ ANSI ย้ายเคอร์เซอร์กลับมุมบนใน Terminal ที่รองรับ ถ้าไม่รองรับให้มีโหมดแสดงเฟรมต่อกัน เกมยังเล่นได้

## 4. โครงสร้างที่เสนอให้ทีมสร้าง

```text
src/
  Main.java             James: เริ่มโปรแกรม
  Game.java             James: รับคำสั่ง เรียกกติกา ตรวจจบเกม
  Player.java           Jezz: HP EXP Level ตำแหน่ง ทิศ กระเป๋า อุปกรณ์
  Dungeon.java          James: แผนที่สองชั้น ช่องเดิน ของ มอน และบันไดลง
  Door.java             James: เงื่อนไขกุญแจและสถานะเปิด
  Enemy.java            Jezz: HP และการต่อสู้ของศัตรู
  Item.java             Jezz: ข้อมูลร่วมและรายละเอียดไอเทม
  Key.java              James: กุญแจและรหัสที่ใช้เปิดประตู
  Potion.java           Jezz: ปริมาณฟื้น HP
  Weapon.java           Jezz: พลังโจมตีเพิ่ม
  Armor.java            Jezz: ค่าลดดาเมจเมื่อ Equip
  AsciiRenderer.java    James: สร้างภาพฉากโดยไม่แก้สถานะ
  TerminalDisplay.java James: รับคำสั่ง Inventory ภาพดาบ HUD และพิมพ์เฟรม
assets/
  ascii/                อาร์ตที่ทีมเลือกแล้ว
docs/
  decisions/            เหตุผลการตัดสินใจสั้น ๆ และผลทดลอง
```

ตอนนี้มี Main.java สำหรับเริ่มโปรแกรมแล้ว ไฟล์ระบบเกมที่เหลือจะเพิ่มตามงาน James/Jezz ถ้าต้องใช้ package ให้ตกลงชื่อและแก้คำสั่ง compile/run ร่วมกัน

- `Key`, `Potion`, `Weapon`, `Armor` สืบทอดจาก `Item` และ override `getDescription()` ให้ใช้ตอนแสดงกระเป๋าจริง
- `Player` มีรายการ `Item` และอ้างถึง `Weapon`/`Armor` ที่ Equip แสดงความสัมพันธ์ has-a
- ถ้ายืนยันว่าเรียน interface แล้ว อาจให้ renderer มีสัญญาร่วมสำหรับตัวแสดงภาพแบบง่ายและแบบละเอียด ใช้เมื่อมีความต้องการจริง
- ให้ `Item` เป็นคลาสแม่ธรรมดาได้ก่อน ถ้าจะใช้ abstract class ให้ยืนยันว่าอยู่ในเนื้อหาที่เรียนแล้ว
- `Game` เรียกความสามารถของคลาสอื่น ไม่รวมสูตรต่อสู้ ภาพ และข้อมูลแผนที่ทั้งหมดไว้ในเมธอดเดียว
- เริ่มเก็บแผนที่และอาร์ตเป็นอาร์เรย์ใน Java ได้ หากเพิ่มการอ่านไฟล์ภายหลัง ให้แยกงานโหลดไฟล์และกรณีไฟล์หาย

สัญญาข้อมูลที่เสนอให้ตกลงใน M0 (ยังไม่ใช่ implementation):

| ข้อมูล/เมธอด | ข้อตกลง |
|---|---|
| พิกัด | x เพิ่มไปขวา, y เพิ่มลงล่าง, อาร์เรย์เข้าถึงด้วย [y][x] |
| ทิศ | 0 เหนือ, 1 ตะวันออก, 2 ใต้, 3 ตะวันตก; หันซ้าย/ขวาวนกลับได้ |
| `Dungeon.isWalkable(x, y)` | นอกแผนที่คืน false; ตรวจประตูและศัตรูที่ขวางด้วย |
| `Player.takeDamage(amount)` | ปริมาณบวกเท่านั้น, HP ต่ำสุด 0 |
| `Player.heal(amount)` | HP สูงสุด maxHp, บอกผู้เรียกได้ว่าฟื้นจริงหรือไม่ |
| `Door.tryOpen(player)` | สำเร็จเฉพาะมีกุญแจที่ตรงกันและยังปิดอยู่ การหักกุญแจรอเลือกก่อน implementation |
| `Player.gainExp(amount)` | เพิ่ม EXP ตรวจเกณฑ์ Level เพิ่ม max HP/ATK โดยไม่เพิ่ม current HP |
| การจัดการ W | Game ตรวจมอนตรงหน้าก่อนการเดิน ถ้าเป็นการตีให้จบคำสั่งที่ช่องเดิม ไม่เดินต่อแม้มอนตาย |
| `Item.getDescription()` | ข้อความรายละเอียดของไอเทมชนิดนั้น ใช้ผ่านชนิด Item ในกระเป๋า |
| `AsciiRenderer.render(dungeon, player)` | James คืนข้อความเฉพาะพื้นที่ฉาก ไม่เปิดประตู ไม่ใช้ยา ไม่ทำให้ศัตรูบาดเจ็บ |
| `TerminalDisplay.readCommand()` | James รับหนึ่งบรรทัดและแยกกรณี EOF ตามที่ทีมตกลง |
| `TerminalDisplay.show(scene, player, message)` | James ซ้อนภาพดาบที่ Equip ประกอบ STATUS/CONTROLS/enemy HP/log แล้วพิมพ์ โดยไม่เปลี่ยนกติกาเกม |

ใครเปลี่ยนชื่อเมธอด ชนิดคืนค่า ทิศ หรือรูปแบบแผนที่ ต้องแจ้งเจ้าของไฟล์ที่เรียกใช้และปรับส่วนเชื่อมให้ครบก่อนรวม main

## 5. ลำดับทำงานและรอบรวมเข้า main

| ช่วง | James — feat/world-view | Jezz — feat/player-combat | ผลที่ต้องได้ |
|---|---|---|---|
| M0: เริ่มต้น | เตรียมจุดเริ่มโปรแกรมและตกลงพิกัด/ทิศ/เมธอด | ตกลงข้อมูล Player/Item/Enemy และ constructor ร่วม | โครงเริ่มต้นรันได้และใช้ชื่อข้อมูลตรงกัน |
| M1: สำรวจ | แผนที่ W/A/D ภาพและ STATUS พื้นฐาน | Player พิกัด/ทิศ/HP และ Item พื้นฐาน | เดินสำรวจได้ |
| M2: ของและประตู | Key/Door จุดเก็บของ หน้า Inventory และภาพดาบ | กระเป๋า Weapon/Armor/Potion และ Equip/Use | เก็บของ สวมอุปกรณ์ ใช้ยา เปิดประตูได้ |
| M3: ต่อสู้ | เชื่อม W กับมอนและแสดง combat log | Enemy ดาเมจ เกราะ HP EXP/Level | ตีแล้วอยู่ช่องเดิม มอนตายไม่สวน Level ไม่เติม HP |
| M4: เกมครบ | เชื่อมสองชั้น บันได จุดจบ เริ่มใหม่ และอาร์ต | ปรับค่าสมดุลและแก้บั๊กข้อมูล/กติกา | เล่นตั้งแต่เริ่มจนชนะหรือแพ้ได้ |

ใช้ main และ branch ของ James/Jezz อย่างละหนึ่ง branch เท่านั้น รวมงานเมื่อส่วนที่ต้องใช้ร่วมกันพร้อม แล้วทั้งคู่นำ origin/main ล่าสุดกลับเข้า branch เดิม รายละเอียด Git อยู่ใน [TEAM_WORKFLOW](TEAM_WORKFLOW.md)

## 6. จุดที่ต้องทำงานร่วมกัน

- Jezz ส่ง Player/Item พื้นฐานก่อน เพื่อให้ James ต่อ Game และ Key ได้
- James เป็นผู้เรียกโจมตี/สวน/ให้ EXP ตามลำดับ ส่วน Jezz คำนวณและเปลี่ยน HP/EXP ผ่านเมธอด
- James เขียนหน้า Inventory และอ่านค่าอุปกรณ์ ส่วน Jezz เขียนการ Equip/Use และกระเป๋า
- กุญแจ/ประตูและการค้นหา matching key อยู่กับ James กระเป๋าของ Jezz ใช้ Item ทั่วไป
- ตัวเลขสมดุลและกติกาที่ยังเปิดไว้เลือกด้วยกันก่อนทำส่วนนั้น

## 7. ผลลัพธ์เมื่อรวมเกมครบ

- เดินและหันได้ ไม่ทะลุกำแพงหรือขอบแผนที่
- W โจมตีมอนเฉพาะช่องติดกันตรงหน้าและอยู่ช่องเดิม รวมถึงครั้งที่ฆ่าได้
- มอนตายไม่สวน ได้ EXP ครั้งเดียว และมีข้อความ HP มอนที่เหลือ
- Equip/Use ผ่าน Inventory ค่าพลังและภาพดาบตรงกับอุปกรณ์ที่สวม
- เกราะลดดาเมจ Heal ไม่เกิน max HP และ Level Up ไม่เพิ่ม current HP
- ประตูใช้กุญแจตรงชนิด ลงชั้นสองได้แต่กลับขึ้นไม่ได้
- ภาพและกรอบข้อมูลสัมพันธ์กับสถานะจริง ข้อความในเกมเป็นอังกฤษทั้งหมด
- เริ่มใหม่แล้วของ มอน ประตู และผู้เล่นกลับสภาพเริ่มต้น

เมื่อมี src/*.java ครบตามโครงสร้างและยังไม่ใช้ package:

```powershell
javac -encoding UTF-8 -d build src/*.java
java -cp build Main
```

build/ อยู่ใน .gitignore และคำสั่ง compile/run ของ Main.java ผ่านการตรวจแล้วตาม README ส่วนระบบเกมจะพัฒนาต่อบนสอง branch ที่แบ่งไว้
