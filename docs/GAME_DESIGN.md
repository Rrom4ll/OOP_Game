# กติกาและแบบเกม

อัปเดตกติกา 17 พฤศจิกายน 2026 ตามคำอธิบายและคำตอบของผู้ใช้ ใช้เอกสารนี้เป็นฐานกติกา ส่วน PROJECT_PLAN เป็นลำดับลงมือทำ และ TEAM_WORKFLOW เป็นการแบ่งงานสองคน วันที่ 18 พฤศจิกายน 2026 มี Main.java สำหรับเริ่มโปรแกรมแล้ว ระบบเกมตามกติกาด้านล่างเป็นงานที่จะพัฒนาต่อ

## 1. แนวเกมและเป้าหมายการเล่น

Java บน Terminal ภาพ ASCII มุมมองบุคคลที่หนึ่ง ข้อความในเกมเป็นภาษาอังกฤษทั้งหมด ผู้เล่นลงดันเจี้ยนโดยไม่มีอุปกรณ์ สำรวจ เก็บของ เปิดประตู ต่อสู้ พัฒนาตัวละคร แล้วลงชั้นถัดไป

อ้างอิงบรรยากาศและมุมมองจาก [Greed & Darkness](https://store.steampowered.com/app/3538070/Greed_Darkness/) ส่วนกติกาที่ใช้จริงเป็นแบบเรียบง่ายตามที่ผู้ใช้กำหนด

- เริ่มออกแบบสองชั้น ชั้นแรกสอนการเดิน ดาบ กุญแจและประตู ชั้นสองใช้เกราะ ยา และ Level ร่วมกัน
- ผังด่าน ตำแหน่งของ ศัตรู ประตู และบันไดถูกกำหนดล่วงหน้าทั้งหมด
- ศัตรูยืนประจำช่อง ไม่เดินไล่ผู้เล่น ไม่มีการสุ่มแผนที่ จุดเกิด หรือของ
- บันไดลงได้อย่างเดียว กลับชั้นก่อนหน้าไม่ได้ คำตอบข้อ 6 ของผู้ใช้ตีความว่าเป็นการยืนยันเรื่องนี้
- มีเส้นทางเลือก เช่น ทางสั้นเจอศัตรูแรง กับทางอ้อมที่มีอุปกรณ์ช่วย ผู้เล่นจัดการเลือดและเลือกเส้นทางเอง
- จำนวนชั้นเริ่มต้นสองชั้นได้รับความเห็นชอบจากข้อเสนอ ส่วนเงื่อนไขชนะปลายชั้นสองยังต้องกำหนด

## 2. หน้าจอและคำสั่ง

- ซ้ายบน: STATUS แสดง Floor, Level, HP/current และ max, EXP, ATK, DEF และอุปกรณ์ที่สวม
- กลางจอ: ภาพทางเดิน ประตู ไอเทม และศัตรูจากทิศที่ผู้เล่นหัน
- กรอบ CONTROLS: อธิบายปุ่มเป็นภาษาอังกฤษตลอด เช่น `W: Forward / Attack`, `A: Turn Left`, `D: Turn Right`, `I: Inventory`
- กรอบ ENEMY: เมื่อศัตรูอยู่ตรงหน้าติดกัน แสดงชื่อและ HP ที่เหลือ เช่น `Goblin HP: 5/12`
- ล่างจอ: เหตุการณ์ล่าสุดและดาเมจของทั้งสองฝ่าย

| ปุ่ม | กติกาที่ยืนยัน |
|---|---|
| W | ตรวจช่องติดกันตรงหน้า ถ้ามีศัตรูมีชีวิต ให้โจมตีหนึ่งครั้งและอยู่ช่องเดิม ถ้าเป็นช่องที่เดินผ่านได้ จึงเดินหนึ่งช่อง |
| A | หันซ้าย 90 องศา ไม่เลื่อนไปช่องข้าง ๆ |
| D | หันขวา 90 องศา ไม่เลื่อนไปช่องข้าง ๆ |
| I | เปิด Inventory เพื่อเลือก Equip หรือ Use |

รุ่นแรกใช้การรับคำสั่งแล้ว Enter ตามแนว Java พื้นฐานที่วางไว้ ไม่มีปุ่มโจมตี F ปุ่มเดินถอย S หรือปุ่มลัดใช้ยา P ในชุดควบคุมที่ยืนยัน

วิธีเลือกหมายเลขไอเทม ปุ่มปิด Inventory และปุ่มออกเกมเป็นรายละเอียด UI ที่ยังปรับได้ ให้มีคำอธิบายภาษาอังกฤษเมื่อออกแบบจริง

## 3. การโจมตีและตำแหน่งผู้เล่น

หนึ่งคำสั่ง W ที่มีศัตรูอยู่ช่องตรงหน้าคือการโจมตีหนึ่งครั้ง ไม่เริ่มต่อสู้อัตโนมัติจนจบ และไม่เปลี่ยนตำแหน่งผู้เล่น

รุ่นแรกใช้ดาเมจคงที่ตามข้อเสนอที่ผู้ใช้เห็นด้วย ไม่มีการสุ่มดาเมจ ส่วนตัวเลขจริง สูตรลดดาเมจขั้นต่ำ และวิธีแสดง overkill ยังต้องเลือก

ลำดับที่ต้องเกิด:

1. ตรวจเฉพาะช่องติดกันในทิศที่หัน ศัตรูที่ด้านข้าง ด้านหลัง หรือไกลออกไปไม่ใช่เป้าหมาย
2. คำนวณพลังโจมตีจากค่าพื้นฐาน โบนัส Level และอาวุธที่ Equip อยู่
3. ลด HP ศัตรูและแสดงดาเมจพร้อม HP ที่เหลือ ห้ามแสดง HP ติดลบ
4. ถ้าศัตรูตาย ให้ได้รับ EXP หนึ่งครั้ง ตรวจ Level Up และไม่ให้ศัตรูสวนกลับ
5. ถ้าศัตรูยังไม่ตาย มันสวนกลับหนึ่งครั้ง คำนวณลดดาเมจจากเกราะที่ Equip แล้วแสดง HP ผู้เล่น
6. ถ้าผู้เล่น HP เป็นศูนย์ ให้ Game Over
7. ผู้เล่นอยู่ช่องเดิมตลอดคำสั่งโจมตี รวมถึงครั้งที่ฆ่าศัตรูตาย ไม่มีการเดินเข้าแทนช่องศัตรูโดยอัตโนมัติ

ระหว่างที่ศัตรูยังมีชีวิต ผู้เล่นเลือกกด W ตีอีกครั้ง หรือกด A/D เพื่อหัน แล้วกด W เดินหนีไปยังช่องที่ผ่านได้ ศัตรูไม่ไล่ตาม

เมื่อศัตรูตายแล้ว ช่องนั้นไม่ถูกมันขวาง การกด W ครั้งถัดไปจึงเป็นการเดินเข้าช่องว่างตามปกติ เป็นการแยกคำสั่งเดินครั้งใหม่ออกจากคำสั่งโจมตีที่เพิ่งจบ

ตัวอย่างข้อความหลังตีแล้วศัตรูยังรอด (ตัวเลขสมมติ):

```text
You hit Goblin for 7 damage.
Goblin HP: 5/12
Goblin hits you for 3 damage.
Your HP: 17/20
```

ตัวอย่างครั้งถัดไปเมื่อฆ่าได้:

```text
You hit Goblin for 7 damage.
Goblin HP: 0/12
Goblin defeated. You gained 5 EXP.
Your HP: 17/20
```

ไม่มีดาเมจสวนกลับหรือการขยับเข้าช่องมอนในตัวอย่างที่สอง

## 4. Inventory และอุปกรณ์

- ผู้เล่นเริ่มตัวเปล่า มีการโจมตีพื้นฐานด้วยมือเปล่า แต่ไม่มีดาบหรือเกราะที่สวม
- เก็บดาบเข้า Inventory อย่างเดียวไม่ได้เพิ่ม ATK ต้องเปิด I แล้วเลือก Equip ก่อน
- Equip ดาบแล้วเพิ่มพลังโจมตีและแสดงภาพดาบในมุมมอง ก่อน Equip ไม่มีภาพดาบ
- เกราะเพิ่ม DEF และลดดาเมจที่ได้รับเฉพาะเมื่อ Equip แล้ว
- ยาต้องเปิด Inventory แล้วเลือก Use ฟื้น current HP ได้ไม่เกิน max HP
- เมื่อเลเวลขึ้น current HP ไม่เพิ่ม ต้องใช้ไอเทม Heal เพื่อเติมส่วนที่ขาด
- การมี matching key อยู่ใน Inventory ทำให้เปิดประตูนั้นได้เมื่อเดินชน ไม่ต้อง Equip กุญแจ

การเก็บของเมื่อเดินเข้าช่องเสนอให้เก็บอัตโนมัติเข้ากระเป๋า แต่การ Equip/Use เป็นการเลือกเองตามที่ผู้ใช้ยืนยัน วิธีเก็บของและข้อจำกัดขนาดกระเป๋ายังเป็นรายละเอียดที่ต้องเลือก

## 5. EXP และ Level

- ฆ่าศัตรูได้รับ EXP ที่กำหนดไว้ ได้ครั้งเดียวต่อศัตรู ไม่มีการฟาร์มศัตรูเกิดใหม่ในขอบเขตเริ่มต้น
- เมื่อครบเกณฑ์ เพิ่ม Level, max HP และพลังโจมตีพื้นฐาน ไม่มีการเติม current HP
- EXP ส่วนเกินควรเก็บต่อ และถ้าได้มากพอข้ามหลาย Level ให้ตรวจเกณฑ์ต่อเนื่อง เป็นรายละเอียด implementation ที่ทีมต้องตรวจด้วยตัวอย่าง

```text
Before: Level 1 | HP 12/20 | ATK 3
After:  Level 2 | HP 12/25 | ATK 4
```

ค่าสมมติเพื่ออธิบายกติกา ยังไม่ใช่ตัวเลขสมดุลจริง ต้องกำหนดตาราง EXP/Level ของทั้งสองชั้นร่วมกับจำนวนศัตรูและยา

## 6. ประตูและชั้นดันเจี้ยน

- เดินชนประตูที่ล็อกแล้วไม่มี matching key จะผ่านไม่ได้ เช่น `Locked. Requires Copper Key.`
- มีกุญแจที่ตรงกันจึงเปิดได้ เช่น `You unlocked Copper Door with Copper Key.`
- ประตูที่เปิดแล้วคงสถานะเปิด ข้อเสนอตั้งต้นคือใช้กุญแจหนึ่งดอกแล้วนำออกจาก Inventory แต่ยังรอเลือกว่าจะให้ใช้แล้วหายหรือเก็บไว้
- การเปิดประตูด้วย W จะอยู่ช่องเดิมหรือเดินผ่านในครั้งเดียวกันยังต้องเลือก เพื่อให้การสอนปุ่มกับโค้ดตรงกัน
- ข้อเสนอการเชื่อมชั้น: ลงบันไดแล้วรักษา HP, EXP, Level, Inventory และอุปกรณ์ที่สวม ย้ายไปจุดเริ่มชั้นถัดไปที่กำหนดไว้ รายละเอียดการส่งต่อสถานะนี้ยังไม่ได้รับคำตอบแยก
- ต้องวางกุญแจ อุปกรณ์ และยาให้มีเส้นทางชนะก่อนลงบันได เพราะย้อนกลับไปเอาของชั้นเดิมไม่ได้

## 7. กติกาเพิ่มเติมที่เสนอและสิ่งที่ยังเปิดไว้

ข้อเสนอเพื่อรักษาความเรียบง่าย ยังไม่ได้รับคำตอบแยกชัดเจน:

- ศัตรูสวนเฉพาะเมื่อถูกโจมตีแล้วรอด การหัน เดินที่อื่น เปิดกระเป๋า และใช้ของไม่ทำให้มันโจมตีเอง ไม่มีการโจมตีรวมจากศัตรูข้างตัวตามจำนวนตา
- สูตรตัวอย่างสำหรับดาเมจคงที่ที่ตกลงแล้ว: `ATK = baseAttack + levelBonus + weaponBonus` และ `receivedDamage = enemyAttack - equippedArmorDefense` ค่าสมดุลและค่าต่ำสุด 0 หรือ 1 ยังต้องเลือก
- ชั้นสองจบด้วยทางออกเป็นตัวเลือกเริ่มต้น เงื่อนไขชนะจริงยังไม่ได้เลือก ไม่ถือว่ามีบอสจนกว่าทีมจะออกแบบและตกลง

รายละเอียดที่ยังต้องสรุป: การเก็บของ, ขนาดกระเป๋า, กุญแจใช้แล้วหายหรือไม่, เปิดประตูแล้วขยับหรือไม่, ผลของการใช้ยาเมื่ออยู่หน้ามอน, ตัวเลขสมดุล และจุดจบเกม

ตารางรายละเอียดเดียวกับ PROJECT_BRIEF เพื่อไม่ให้ผู้รับงานตีความข้อเสนอเป็นกติกาที่ล็อกแล้ว:

| เรื่อง | ยังต้องเลือก |
|---|---|
| การเก็บของ | อัตโนมัติเมื่อเดินถึง หรือมีคำสั่งเก็บ |
| การใช้ยา/เปิดกระเป๋าต่อหน้ามอน | เสนอว่าไม่สวนเอง แต่ยังไม่ยืนยันแยก |
| กุญแจ | ใช้แล้วหายหรือเก็บไว้ |
| เปิดประตูด้วย W | อยู่ช่องเดิมหรือเดินเข้าช่องประตูทันที |
| กระเป๋า/เปลี่ยนอุปกรณ์ | จำนวนช่อง การแทนของเดิม การเลือกหมายเลข และปุ่มกลับ |
| ยาขณะเลือดเต็ม | เสนอให้ไม่เสียยา แต่ยังต้องเลือกนโยบายการใช้/หักจำนวน |
| ดาเมจขั้นต่ำ | 0 หรือ 1 หลังหัก DEF |
| ดาเมจที่แสดงเมื่อโจมตีเกิน HP | พลังโจมตีเต็ม หรือ HP ที่ถูกหักจริง |
| สมดุล | ค่าเริ่มต้น ของ มอน ยา EXP threshold และโบนัส Level |
| EXP | รูปแบบ HUD แบบสะสม/เฉพาะ Level และการเก็บ EXP ส่วนเกิน/ข้ามหลาย Level |
| เปลี่ยนชั้น | ลงทันทีหรือถามยืนยัน ถ้าลงทันทีเสนอให้เตือนตั้งแต่ยืนหน้าบันได |
| สถานะข้ามชั้น | เสนอให้รักษา HP, Level, EXP, Inventory และอุปกรณ์ที่สวมทั้งหมด |
| นโยบาย log | สรุปเหตุการณ์ให้พอดี หรือมีประวัติ/แบ่งหน้าเมื่อข้อความยาว |
| จุดจบเกม | เสนอทางออกท้ายชั้นสอง ยังไม่มีเงื่อนไขชนะที่ยืนยัน |

## 8. กรณีตรวจรับที่สำคัญ

- W ต่อหน้าศัตรูที่รอดและที่ตาย: พิกัดผู้เล่นก่อน/หลังต้องเท่ากันทั้งคู่
- ศัตรูที่ไม่อยู่ช่องตรงหน้าไม่ถูกโจมตีเมื่อกด W
- ศัตรูที่ถูกฆ่าไม่สวนกลับ EXP ได้ครั้งเดียว HP ศัตรูแสดงอย่างน้อย 0
- หันแล้วเดินหนีได้เมื่อมีทาง ศัตรูยังอยู่ช่องเดิม
- ดาบ/เกราะที่อยู่ในกระเป๋าแต่ไม่ Equip ไม่มีผลกับค่า ATK/DEF และภาพดาบ
- Level Up เปลี่ยน max HP กับ ATK แต่ current HP คงเดิม
- ประตูที่ใช้กุญแจคนละชนิดยังล็อก ลงบันไดแล้วกลับชั้นก่อนหน้าไม่ได้
- ตัวอย่างข้อความทั้งเกมเป็นอังกฤษ และมี enemy HP ที่เหลือใน UI/บันทึกต่อสู้
